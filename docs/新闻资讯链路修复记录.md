# 新闻资讯链路修复记录（Huntly 挂载 + enrichment 全中性/回退）

> 2026-11-21 实测修复。现象、根因、修法、验证全记录，换环境部署或再次出现同类问题时按此排查。
> 涉及：`docker-compose.yml`、`backend/services/api/news/enricher.py`、`.env`、PG `news_article_enrichment`。

---

## 现象

1. **新闻资讯页一条文章都看不到**：左侧来源计数正常（同花顺/财联社/华尔街见闻/格隆汇/金十/财新/36氪，99+ 等），统计"共 2,032 篇"，但列表区"当前筛选无文章"，`最新: —`。
2. **修复列表后情感全是中性**：`利好 0 / 利空 0 / 中性 2032`。
3. **全量重建后最新 ~200 篇又被改回词典版**：force 重建明明全部成功，几分钟后 `model_version` 不带 `+finbert` 的行又出现 200 条，和重建互相拉锯。

## 根因（三层叠加）

### ① 列表为空：Huntly SQLite 挂载不一致

- `.env` 的数据根 `QM_DATA_HOST_PATH=\\wsl$\Ubuntu-24.04\home\liao\quantmind-data`（WSL 路径），quantmind/celery 等容器的 `/data` 都指向它；
- 但 **huntly 容器**挂的是仓库相对路径 `./data/huntly:/data`（D 盘 `D:\gitProject\QuantMind\data\huntly`），实时资讯库（2,500+ 篇）一直写在 D 盘；
- 后端 news 模块**直读 Huntly SQLite**（`HUNTLY_SQLITE_PATH=/data/huntly/db.sqlite`）→ 读到 WSL 里 11 月 13 日的旧库，`page` 表 **0 行** → 列表恒空；
- 来源计数与"共 N 篇"来自 PG enrichment 表和 connector 清单，所以统计正常、列表为空，两边对不上。

### ② 全是中性：词典表空 + FinBERT 模型缺失

- 情感分 = `0.6 × 词典法 + 0.4 × FinBERT(置信度≥0.55)`；
- PG 的 `finance_lexicon` / `stock_aliases` **0 行**（本地库从未跑种子脚本）→ 词典分恒 0；
- `/app/models/finbert-zh-base/` **不存在**（模型从未下载），且 `FINBERT_DEVICE=-1` 默认关 → FinBERT 分支不生效；
- 两者皆缺 → 所有文章 `dict_score=0` → 全部 neutral。

### ③ 反复回退：target 版本依赖"各进程运行时加载态"（代码 bug）

- `enricher._current_target_version()` 原来用 `sentiment_mod.is_available()` 判定是否带 `+finbert` 后缀，而 `is_available()` 依赖**当前进程**的 `_model_ready`；
- FinBERT 是懒加载的：**celery-worker 进程**从没主动加载过模型 → 它眼里的目标版本=无后缀的词典版；
- 于是每分钟的增量批次（`news_enrich_recent`，limit=200，只处理最新 200 篇）在 celery 进程里把"版本 != 词典版"的最新文章全部**重写成词典版**——刚好把 api 进程 force 重建刚写好的 FinBERT 结果降级，形成拉锯。实测 200 行 plain 的 `enriched_at` 与重建窗口完全交错。

## 修复动作

### 1. compose 补挂载（修①）

`docker-compose.yml` quantmind 服务 volumes 增加：

```yaml
- ./data/huntly:/data/huntly   # 后端直读 huntly 实时库；否则读到 WSL 旧库（page 0 行）
```

### 2. 词典种子（修②前置）

```bash
docker exec quantmind python backend/scripts/import_sentiment_lexicon.py
docker exec quantmind python backend/scripts/seed_a_share_stocks.py
docker exec quantmind python backend/scripts/seed_event_categories.py
docker exec quantmind python backend/scripts/seed_geo_entities.py
```

结果：`finance_lexicon` 52,311 条、`stock_aliases` 17,002 条。

### 3. FinBERT 模型下载（修②）

```bash
docker exec quantmind python backend/scripts/download_finbert.py
# 模型 bardsai/finance-sentiment-zh-base，源顺序：ModelScope → hf-mirror → HF
```

**坑**：容器内大文件 `model.safetensors`(409MB) 能下，但 5 个小文件（config/tokenizer 等）被 403/断网。解决办法：**宿主机**用 `https://hf-mirror.com/<repo>/resolve/main/<file>` 逐个下载到 `temp/finbert_dl/`，再 `docker exec -i quantmind sh -c "cat > /app/models/finbert-zh-base/<file>" < <file>` 灌进去（容器是 root，绕开 `\\wsl$` 的写权限问题）。6 个文件齐全后重跑脚本会自动跳过已存在文件。

### 4. 开启 FinBERT（修②）

`.env` 追加 `NEWS_USE_FINBERT=true`（compose 透传给容器），`FINBERT_DEVICE=-1` 走 CPU（实测 ~34ms/篇）。然后 `docker compose up -d quantmind` 重建容器使 env 生效。

### 5. 修版本退化 bug（修③，代码改动）

`backend/services/api/news/enricher.py` 两处：`_current_target_version()` 和 `run_full_rebuild` 里的 target 判定，由 `sentiment_mod.is_available()`（依赖进程内 `_model_ready`）改为 **`sentiment_mod.is_finbert_enabled()`**（配置级开关），并加注释说明原因。这样 api 进程与 celery 进程的目标版本一致，增量批次不再降级。

### 6. 全量重建

```bash
# 登录拿 token 后：
curl -X POST "http://127.0.0.1:8000/api/v1/news/enrichment/rebuild-all?force=true" -H "Authorization: Bearer $TOKEN"
# 进度：GET /api/v1/news/enrichment/rebuild-progress
```

## 验证结果（2026-11-21 实测）

- 文章列表：`GET /api/v1/news/articles` 返回 2,597+ 篇，`latest_published_at` 实时推进；
- 全量重建：2,633→2,637 篇全部成功、0 失败（FinBERT CPU ~34ms/篇，总耗时 ~2 分钟）；
- `model_version`：重建 + 2 个 beat 周期后**仅剩 `ac-v5+lex-v4+ent+cn+finbert` 一种**（2,637 行），无降级残留；
- 情感分布：利好 1,062 / 中性 791 / 利空 784；
- 新文章由 celery-beat 每分钟的 `news_enrich_recent` 增量入库，自动带 FinBERT 标签。

## 新环境部署检查单（新闻链路）

1. huntly 的 SQLite 必须与后端 `HUNTLY_SQLITE_PATH` 指向**同一份文件**（本仓库用 `./data/huntly` 直通挂载解决）；
2. 跑 4 个种子脚本（词典/别名/事件/地理）——空词典 = 全中性；
3. 跑 `download_finbert.py` 补模型（小文件 403 时按上面宿主机下载+docker exec 灌入）；
4. `.env` 设 `NEWS_USE_FINBERT=true`，重建 quantmind；
5. 触发一次 `rebuild-all?force=true`，并确认 `model_version` 全部带 `+finbert`、跨 beat 周期不回退。

## 排错入口

- 列表空：先看 `docker exec quantmind ls -la /data/huntly/`（文件在不在、多大），再查 `_huntly_sqlite_available()`；
- 全中性：查 `SELECT COUNT(*) FROM finance_lexicon` 与 `/app/models/finbert-zh-base/` 是否存在；
- 标签回退：对比 api 与 celery 两个进程日志里的 FinBERT 加载行，确认两边 `is_available()` 都为 True；
- FinBERT 状态一键查看：容器内 `sentiment.get_finbert_status()`（enabled/model_ready/model_failed/override）。
